# Temas guardados (API y MCP)

Un tema es una copia completa de `theme`, `alerts`, `overlay`, `widgets`, la **configuración** de interactivos (preguntas, tier list y sorteo), `commands` y `timers`. Viajan también sus valores operativos: acciones, plataformas, mínimos, objetivos y mensajes, no solo colores o CSS. Los cambios corrientes editan el tema activo. El estado del directo (cola, preguntas, votos, participantes y contadores) no pertenece al tema.

Las conexiones y secretos, las sesiones, Meld/OBS y su configuración, Discord, calendario, acceso, puerto, panel, dock, prompter y teleprompter son globales. El HTML, CSS y JavaScript propios y los permisos de los overlays son globales. Su CSS adicional por tema vive en `customOverlayCss`, un mapa `{ idOverlay: css }`: se copia al duplicar y se sustituye al activar. Una entrada ausente equivale a CSS vacío. Cambiar de tema no modifica escenas ni fuentes de navegador.

## Panel y dock

En **Ajustes › Apariencia › Temas** selecciona un tema para ver las capas reales de alerta, objetivo y chat sin activarlo. Las muestras usan sus colores, textos, diseño, medios y CSS guardados. Desde ahí puedes activarlo, duplicarlo, editarlo o borrar uno inactivo. **Nuevo tema** crea una copia completa del tema elegido o parte de **Color de cada plataforma**. El máximo es 10; primero activa otro para borrar el activo.

Para compartir uno, selecciónalo y pulsa **Exportar**. **Importar tema** abre un ZIP y muestra el nombre sugerido, los medios, las colisiones y los avisos antes de crear una copia nueva inactiva. Puedes elegir otro nombre; no se reemplaza ni se activa ningún tema. El límite sigue siendo 10.

Al crear o editar un tema puedes asignarle un avatar: imagen, color o ambos (la imagen se recorta en círculo y el color dibuja el anillo). Se muestra en las listas de Apariencia, el selector lateral, el dock y la lista de origen. Sin avatar se usa el acento o el indicador multicolor del tema por plataformas. Se suben imágenes PNG, JPG/JPEG, WebP o GIF; no se admiten SVG, APNG ni AVIF. Duplicar copia el aspecto y ajustes, pero no el avatar: el tema nuevo tiene identidad propia. Quitar un avatar o borrar un tema no borra los archivos de media.

El selector destacado al pie de la barra lateral y la pestaña **Tema** del dock cambian el tema en el momento; las tres superficies se sincronizan sin recargar. Los cambios corrientes y los resets de alertas o Apariencia afectan solo al activo. Si cambias desde el panel con un borrador local, se pide confirmación antes de descartarlo. Si otro cliente activa un tema, el borrador anterior permanece visible, Guardar se bloquea y puedes descartarlo; no se aplica al tema nuevo. La apariencia de serie para instalaciones nuevas usa el color y el logo de cada plataforma. Ya no se ofrece el selector «Punto de partida».

## API

- `GET /api/themes` devuelve `{ "themes": [{ "id", "name", "active", "avatar"? }] }`; `avatar` es `{ "image"?: "foto.png", "color"?: "#RRGGBB" }` y queda fuera del look.
- `GET /api/themes/:id/export` descarga un ZIP con `config.json` (`format: "antena-theme"`, `kind: "theme"`, `version: 1`, `app` y `theme: { name, avatar?, look }`) y los archivos `media/<nombre>` referenciados. Para el activo toma las secciones en vivo; un medio directo o avatar ausente o no normal, o un medio demasiado grande, impide la exportación. Un medio usado solo en CSS que falta o no es un archivo normal se omite y se avisa al previsualizar la importación.
- `POST /api/themes/import/preview` recibe el ZIP con `Content-Type: application/zip` y devuelve `{ name, suggestedName, media: { count, size, conflicts }, warnings, fingerprint }` sin escribir. Para aplicar, envía el mismo ZIP a `POST /api/themes/import`, con `X-Config-Fingerprint` y, opcionalmente, `?name=<nombre>`; crea un tema inactivo y devuelve `{ theme, warnings }`. Si cambió la configuración o los medios, repite la vista previa. Un nombre existente sugiere ` (2)`, ` (3)`…, y un nombre elegido que ya existe responde 409.
- `GET /api/themes/:id/look` devuelve una proyección resumida sin acciones, comandos, timers ni CSS; el activo se lee de las secciones actuales.
- `GET /api/themes/:id/preview` entrega `activeTheme: { id, name }` y solo los datos necesarios para pintar la alerta de muestra y los widgets de objetivo y chat (incluidos CSS y medios), sin acciones ni secciones operativas. El parámetro opcional `type` elige cualquier tipo de alerta (por defecto `follow`). La vista del overlay lo usa con `?still=<tipo>&previewTheme=<id>` y los widgets con `?demo&previewTheme=<id>`; nunca se activa ni se guarda el tema.
- `POST /api/themes/duplicate` con `{ "from": "normal", "name": "Navidad", "avatar": { "color": "#112233" } }` copia el tema activo o uno inactivo sin copiar su avatar; `avatar` es opcional.
- `POST /api/themes/from-default` con `{ "name": "Plataformas", "avatar": { "image": "foto.png" } }` crea desde la configuración de serie con «Color de cada plataforma» (`platformAccent: true`, `platformBadge: "logo"`); `avatar` es opcional.
- `PUT /api/themes/:id` acepta `name` y/o `avatar`; renombrar no cambia el id. En `avatar`, las claves omitidas se conservan, `image: ""` o `color: ""` quitan solo ese campo y `avatar: null` quita ambos. La imagen debe ser el nombre de un archivo existente en media (sin rutas); súbela primero con `POST /api/media/upload?name=<nombre>` y usa el `name` devuelto.
- `POST /api/themes/:id/activate` activa el tema; repetirlo para el activo no escribe ni crea copia.
- `DELETE /api/themes/:id` borra un tema inactivo. El activo responde 409: «Activa otro tema antes de borrar este».

En **Personalizados** (antes «Overlays»), «CSS de este tema» se guarda en el tema activo. Se aplica en vivo tras el CSS propio mediante la shell y `postMessage` al marco sandbox, sin recargarlo ni cambiar `updatedAt` o permisos. Se valida como CSS de hasta 512 KB de JSON por overlay; el mapa admite hasta 50 entradas y 2,5 MB de JSON. También se puede escribir con `POST /api/config/set` y `{ "path": "customOverlayCss.<id>", "value": "…" }`. Las escrituras de elementos del panel llevan `X-Antena-Theme` con el id contra el que se editó. Si ya no es el activo, responden 409 «El tema activo cambió mientras editabas; tus cambios no se guardaron» sin escribir. API y MCP sin esa cabecera conservan el comportamiento de editar el activo.

Los nombres se recortan en los extremos, deben ser únicos sin distinguir mayúsculas y tener de 1 a 40 caracteres. Los ids son slugs únicos; el máximo es 10 temas. Una referencia desconocida responde 404 y un look que no supera el esquema responde 400 antes de guardar. Los cambios genéricos de configuración no pueden escribir `themes`: usa estas rutas. La configuración pública y `/api/state` muestran ids, nombres y cuál está activo, sin los looks inactivos; la exportación completa de configuración sí los incluye.

El `<html>` del overlay, widgets y marco propio recibe `data-tema="<id>"`; las previews `previewTheme` usan el id elegido. Los widgets y el marco propio cambian el marcador inmediatamente; si hay una alerta visible, el overlay difiere el marcador junto con el aspecto hasta que la alerta termine de salir. En `/api/stream`, `?themeInfo=1` añade `activeTheme: { id, name }` después de las tramas iniciales existentes; está separado de `theme` y de su `version`, por lo que renombrar no cambia el hash de apariencia ni las miniaturas. La shell solicita además `customTheme=1` para recibir el snapshot `customOverlayTheme`; los clientes sin estos parámetros conservan su secuencia anterior. En overlays propios `antena.on('theme', fn)` y `antena.state.theme` incluyen `id` y `name` junto con las variables habituales. Una instantánea única lleva identidad, aspecto y CSS del overlay; el SDK aplica ambos CSS y el marcador antes de notificar el evento.

Con `?build=1`, `/api/stream` añade al final de las tramas iniciales `build: { version }`, la versión de Antena. El overlay de alertas, los widgets y la shell de los overlays propios la piden y se recargan una sola vez si, al reconectar, la versión es distinta de la primera que recibieron: tras actualizar Antena, las fuentes abiertas en OBS o Meld cargan el código nuevo sin refrescarlas a mano. Un reinicio con la misma versión no recarga nada (#355).

Activar guarda el look saliente, aplica el entrante y actualiza `activeId` en una única escritura atómica con copia local previa. El cambio se difunde a los overlays, widgets y panel. Las alertas que ya están en pantalla o en la cola del overlay conservan los ajustes de alerta y CSS con los que se construyeron; las alertas construidas después del cambio usan los del nuevo tema. El tema global del overlay cambia entre alertas, no durante la salida de la actual. Se descarta cualquier borrador de Apariencia del tema anterior. Un objetivo o variante de chat inexistente se rechaza en su API con 404 sin cambiar contadores ni configuración; los atajos actuales no incluyen acciones de objetivo o variante.

## Stream Deck

`GET /sd/tema/<id>` o `POST /sd/tema/<id>` activa el tema por su id usando la misma transacción y notificaciones que la API. Un id inexistente responde 404 sin cambios.

## MCP

`exportar_tema { id, ruta }` escribe el ZIP en una ruta local nueva sin sobrescribir, e `importar_tema_guardado { ruta, nombre?, confirmar? }` lo previsualiza o crea el tema inactivo con `confirmar: true`. Son distintos de `importar_tema`. `listar_temas`, `duplicar_tema { id, nombre }`, `renombrar_tema { id, nombre, color?, imagen? }`, `activar_tema { id, confirmar: true }` y `borrar_tema { id, confirmar: true }` usan la misma API. En `renombrar_tema`, `color` e `imagen` son opcionales; una cadena vacía quita ese campo, sin borrar el archivo. La activación y el borrado requieren confirmación de la persona antes de invocar la herramienta. `restaurar_tema` restaura el aspecto de serie; `tema_de_partida` se conserva por compatibilidad solo con el id `plataforma`.

### Crear y editar con un agente

El prompt MCP `disenar_tema` guía al agente, una cuestión cada vez, por el nombre, avatar, base, colores, tipografía, forma, textos y medios por alerta, widgets y CSS de overlays. Si necesita un archivo, pide autorización para `importar_archivo`. Crea con `crear_tema { nombre, desde?, color?, imagen? }`: sin `desde` parte de Color de cada plataforma; con un id copia su look completo. El tema nuevo siempre queda inactivo y no copia el avatar de origen. `imagen` es un nombre de media raster ya importado.

Las herramientas de alertas y variaciones, apariencia y CSS, widgets y variantes de chat, objetivos y barras, comandos, mensajes programados e interactivos aceptan `tema: <id>` para leer o editar ese look guardado. También lo admiten `ver_config`, `cambiar_config`, `fijar_valor` y `borrar_valor` para las rutas de tema, y `css_overlay_tema { id, css?, tema? }` lee o sustituye el CSS adicional de un overlay sin cambiar su código ni permisos. Por ejemplo: `editar_alerta { tipo: "follow", cambios: { title: "¡Bienvenido!" }, tema: "navidad" }`. Sin `tema`, o con el id activo, todo funciona como antes. Un id desconocido responde 404; una ruta global o una mezcla de secciones de tema y globales se rechaza para un destino inactivo.

`importar_tema { tema: { accent: "#123456" } }` conserva su contrato anterior. Para importar apariencia en otro tema se usa `importar_tema { tema: "navidad", aspecto: { accent: "#123456" } }`: al indicar un id, `aspecto` es obligatorio y debe ser un objeto. Las operaciones de borrado y restauración que ya exigían `confirmar` siguen exigiéndolo. `sumar_objetivo`, `fijar_objetivo`, `sumar_barra` y `fijar_barra` no aceptan `tema`: cambian contadores reales del directo, no el look. Del mismo modo, no se dirigen a un tema inactivo los lanzamientos, envío de mensajes, preguntas, votos ni sorteos en vivo. Las lecturas de widgets e interactivos incluyen sus datos del directo habituales; los datos de ejecución de mensajes de un tema inactivo no son los del planificador activo.

Muestra `/overlay?still=<tipo>&previewTheme=<id>` y `/widget/<nombre>?demo&previewTheme=<id>` (en un objetivo añade `&id=<idObjetivo>`). Activa únicamente si la persona lo solicita expresamente y confirma.

Para clientes HTTP, `X-Antena-Target-Theme: <id>` dirige esas mismas rutas de configuración al tema; es distinto de `X-Antena-Theme`, que sigue siendo la cerca de borrador del panel. El servidor ejecuta el handler y la validación existentes sobre una copia aislada por petición, sin sustituir la configuración viva. Antes de guardar un tema inactivo valida además el look completo con el mismo esquema que la activación: un valor que algún handler antiguo permita para el activo puede rechazarse aquí con 400, sin guardar nada. La edición del activo conserva su comportamiento anterior. Una escritura confirma el look completo mediante una transacción atómica con comprobación de concurrencia, sin crear ni retirar copias de seguridad; si cambió durante la edición devuelve 409. Solo se actualiza el panel, nunca los overlays ni sus temporizadores. Las secciones y acciones globales no están admitidas para un destino inactivo.

## Migración y copia

Al abrir una configuración anterior a v3 se conserva una copia privada de los bytes anteriores y se crea el tema activo «Normal». Se fusionan y guardan los defaults vigentes de todas las secciones del tema: tema, alertas, overlay, widgets e interactivos, junto con las listas de comandos y timers y el mapa CSS de overlays. En cada variación se guardan las condiciones efectivas, incluidos los defaults ausentes. En comandos y timers antiguos incompletos se materializan además los campos que usa el constructor de su alerta, con sus respectivos defaults efectivos; no se inventan permisos, cooldowns ni ajustes de programación ausentes. Así, cambios posteriores a esos defaults no cambian el aspecto existente. Una instalación nueva usa Color de cada plataforma; una instalación v2 que actualice directamente conserva los defaults anteriores (acento sin plataforma y etiqueta de texto).

La transferencia individual incluye las secciones completas del elemento y el avatar, pero no conexiones, sesiones ni código de overlays propios. Enumera archivos de alertas y variaciones, comandos, timers, fuentes, iconos, sonido, avatar y referencias CSS en `url(...)` o `@import` con cadena, incluidos los `src` de `@font-face` y sus pistas `format()`. Los temas pueden incluir archivos `.css` de `media/` referenciados directamente; no se recorren sus dependencias internas. Los archivos idénticos existentes se reutilizan y las colisiones diferentes se renombran con sus referencias; se conservan comillas, escapes CSS, codificación porcentual, consultas y fragmentos. El CSS de un overlay ausente se omite con aviso.

Las rutas CSS se resuelven frente a la página que las muestra: en `/overlay`, `media/x.png`, `./media/x.png` y `../media/x.png` apuntan a `/media/x.png`; en `/widget/*`, solo `../media/x.png` de esas rutas relativas apunta allí; en `/custom/<id>/frame`, hace falta `../../media/x.png`. `/media/x.png` sirve en las tres. Esto presupone que el código propio no cambia la URL base del marco. Las referencias que no resuelven a un archivo portable de `media/` y los medios CSS ausentes se avisan en la vista previa y se dejan intactos; no se siguen ni se descargan. Las URLs absolutas, incluso `http://127.0.0.1:<puerto>/media/…` del equipo de origen, se tratan como externas: pueden apuntar a otra app al importar y se conservan con aviso. Los ZIP usan los mismos límites y comprobaciones de nombres y enlaces que la copia completa; el avatar debe ser raster y un archivo normal. Como acciones, mensajes y CSS son texto libre, revísalos antes de compartir un tema.

La copia local `config.backup-…json` puede contener datos privados y debe protegerse. La exportación e importación completas de configuración incluyen los temas guardados y siguen sus reglas normales de revisión y copia.

La copia completa en ZIP incluye los archivos `.css` de la carpeta de medios referenciados directamente desde el aspecto activo o desde los aspectos de temas guardados, con las mismas reglas de nombres y límites que los demás medios. Los CSS no referenciados se omiten y aparecen en el informe; una importación que los incluya se rechaza. No se siguen referencias a archivos adicionales dentro de esos CSS ni URLs externas, y el listado de medios sigue ocultando los `.css`.
